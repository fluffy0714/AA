# Интеграции АА: проверка 22 октября 2026

## Результат

Сценарий полностью реализуем внутри АА на уровне интерфейса и расчётной модели.
Для реальных данных и оформления нужны согласованные интеграции. **Не установлено,
что «официальных API нет».** У Купера найдены релевантные официальные продукты.
У Яндекса проверенный Retail API решает другую, партнёрскую задачу.

| Возможность | Купер | Яндекс Еда |
| --- | --- | --- |
| Официальная документация | Подтверждена | Подтверждена |
| Клиентские приложения, каталог и корзина | Заявлены на портале Client apps API; методы и доступ АА не подтверждены | В изученном Retail API потребительский сценарий не подтверждён |
| Опции доставки и размещение заказа внешней витриной | Документированы в Fulfillment API; применимость к АА требует согласования | Retail API описывает получение магазином заказов от Яндекса |
| Полная потребительская цена с персональными скидками | Не подтверждена для АА | Не подтверждена для АА |
| Deep link с готовой корзиной в приложение | Не подтверждён | Не подтверждён |
| Выданные АА ключи, договор, sandbox | Нет в этой сессии | Нет в этой сессии |

## Первичные источники и пределы выводов

1. [Купер Интеграции](https://docs.kuper.ru/): портал описывает Client apps API
   для клиентских приложений, включая каталог, корзину, промокоды, оплату и доставку.
   Это подтверждает заявленное направление, но не выдачу доступа нашему проекту.
   Контакт интеграций на портале: `new.partners@sbermarket.ru`, технический:
   `kuper-api@kuper.ru`. Сообщения не отправлялись.
2. [Client apps API](https://docs.kuper.ru/api-products/sbermarket/description):
   прямая ссылка из официального меню. Доступное текстовое представление содержало
   только навигацию и контакты; подробную спецификацию по этой ссылке получить
   не удалось. Не придумываем методы, авторизацию и права доступа.
3. [Fulfillment API](https://docs.kuper.ru/api-products/fulfillment/swagger):
   документирует размещение заказа внешними витринами, магазины по координатам,
   опции и стоимость интервалов доставки, способы оплаты, создание и отмену заказа.
   Нельзя автоматически приравнивать это к потребительской корзине в приложении
   Купера или к универсальному доступу ко всем магазинам. Для этого нужны отдельные
   ответы партнёра. Прикладная реализация этих методов пока не написана.
4. [Яндекс Retail API](https://yandex.ru/support/retail/ru/ref/): интеграция с кассовой
   системой партнёра. В PULL-модели Яндекс запрашивает номенклатуру у магазина и
   создаёт заказ в системе магазина. Метод `POST /order` в этой схеме не является
   доказательством возможности АА разместить потребительский заказ в Яндекс Еде.
5. [Яндекс Еда Vendor API](https://yandex.ru/dev/eda-vendor/doc/ru/ref/):
   интеграция ресторанов, включая PULL и Vendor Management. Не подменяет
   потребительскую интеграцию.

Проверка использовала официальный контент через веб-поиск и чтение страниц.
Прямой HTTP-запрос к документации Купера из среды вернул страницу ограничения
доступа с просьбой отключить VPN. Ограничение не обходилось. Это препятствие
конкретного доступа, а не доказательство отсутствия API.

## Следующий шаг по интеграциям

Подготовленный список вопросов для партнёрских отделов (не отправлен):

- Может ли независимое приложение сравнивать итоговую корзину с другим агрегатором?
- Какой продукт подходит: Client apps, Fulfillment или отдельный партнёрский API?
- Какие магазины и регионы доступны, как определяются SKU, упаковки и остатки?
- Есть ли полный quote до создания заказа: товары, доставка, сервисный сбор,
  надбавка за спрос, промокоды, подписки, персональные скидки, срок действия?
- Можно ли передать готовую корзину в приложение без повторного добавления?
- Если оформление внутри АА: как устроены пользовательская авторизация, оплата,
  идемпотентность, ошибки, отмены и повторное подтверждение изменившейся цены?
- Какие договор, sandbox, ключи, лимиты, правила хранения и отображения данных нужны?

До этих ответов не подключаем внутренние потребительские API, браузерные сессии,
скрейпинг закрытых данных и не показываем вымышленные цены как реальные.
